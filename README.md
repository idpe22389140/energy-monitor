## Περιγραφή Σεναρίου

Η εφαρμογή αναπτύχθηκε για ένα βιομηχανικό εργοστάσιο παραγωγής που αποτελείται από πολλαπλές ζώνες εργασίας όπως γραμμές παραγωγής, αποθήκη και γραφεία. Κάθε ζώνη περιέχει μηχανήματα με διαφορετικές ενεργειακές ανάγκες.

Το σύστημα καταγράφει την ενεργειακή κατανάλωση σε kWh για κάθε μηχάνημα ξεχωριστά. Με αυτό τον τρόπο η διοίκηση του εργοστασίου μπορεί να:

- Παρακολουθεί σε πραγματικό χρόνο πόση ενέργεια καταναλώνει κάθε μηχάνημα
- Εντοπίζει μηχανήματα με υπερβολική κατανάλωση
- Συγκρίνει την κατανάλωση μεταξύ διαφορετικών ζωνών
- Βλέπει τάσεις κατανάλωσης ανά ημέρα και εβδομάδα
- Βελτιστοποιεί την ενεργειακή αποδοτικότητα του εργοστασίου

## Δομή Βάσης Δεδομένων

Η βάση δεδομένων ονομάζεται `energy_monitor` και αποτελείται από 3 πίνακες:

### Πίνακας 1: `zones` — Ζώνες εργοστασίου

| Πεδίο | Τύπος | Περιγραφή |
|-------|-------|-----------|
| id | INT AUTO_INCREMENT PRIMARY KEY | Μοναδικό αναγνωριστικό |
| name | VARCHAR(100) NOT NULL | Όνομα ζώνης |
| description | TEXT | Περιγραφή της ζώνης |
| created_at | TIMESTAMP | Ημερομηνία δημιουργίας |

### Πίνακας 2: `machines` — Μηχανήματα

| Πεδίο | Τύπος | Περιγραφή |
|-------|-------|-----------|
| id | INT AUTO_INCREMENT PRIMARY KEY | Μοναδικό αναγνωριστικό |
| zone_id | INT FOREIGN KEY | Αναφορά στον πίνακα zones |
| name | VARCHAR(100) NOT NULL | Όνομα μηχανήματος |
| model | VARCHAR(100) | Μοντέλο μηχανήματος |
| rated_power_kw | DECIMAL(8,2) | Ονομαστική ισχύς σε kW |
| status | ENUM | active / inactive / maintenance |
| created_at | TIMESTAMP | Ημερομηνία δημιουργίας |

### Πίνακας 3: `energy_readings` — Μετρήσεις κατανάλωσης

| Πεδίο | Τύπος | Περιγραφή |
|-------|-------|-----------|
| id | INT AUTO_INCREMENT PRIMARY KEY | Μοναδικό αναγνωριστικό |
| machine_id | INT FOREIGN KEY | Αναφορά στον πίνακα machines |
| kwh | DECIMAL(10,3) NOT NULL | Κατανάλωση σε kWh |
| recorded_at | DATETIME NOT NULL | Ημερομηνία και ώρα μέτρησης |
| notes | TEXT | Προαιρετικές σημειώσεις |
| created_at | TIMESTAMP | Ημερομηνία εισαγωγής |

**Σχέσεις μεταξύ πινάκων:**
- Κάθε `zone` έχει πολλά `machines` (1 προς Ν)
- Κάθε `machine` έχει πολλά `energy_readings` (1 προς Ν)

## Σελίδες Εφαρμογής

### 1. Dashboard (index.php)
Η κεντρική σελίδα της εφαρμογής. Εμφανίζει:
- Συνολική κατανάλωση της ημέρας σε kWh
- Συνολική κατανάλωση της εβδομάδας σε kWh
- Αριθμό ενεργών μηχανημάτων
- Μηχάνημα με τη μεγαλύτερη κατανάλωση
- Γράφημα ημερήσιας κατανάλωσης (bar chart) για τις τελευταίες 7 ημέρες
- Γράφημα κατανάλωσης ανά ζώνη (doughnut chart)
- Πίνακα με τις 8 πιο πρόσφατες μετρήσεις

### 2. Καταχώρηση Μέτρησης (add_reading.php)
Φόρμα για την εισαγωγή νέας μέτρησης. Περιλαμβάνει:
- Dropdown επιλογής μηχανήματος (ομαδοποιημένο ανά ζώνη)
- Πεδίο εισαγωγής kWh
- Επιλογή ημερομηνίας και ώρας
- Πεδίο σημειώσεων (προαιρετικό)
- Επιβεβαίωση επιτυχούς καταχώρησης

### 3. Ιστορικό (history.php)
Σελίδα αναζήτησης και ανάλυσης. Περιλαμβάνει:
- Φίλτρα αναζήτησης (ημερομηνία, ζώνη, μηχάνημα)
- Σύνολο εγγραφών, kWh, μέσο όρο και μέγιστο
- Πίνακα αποτελεσμάτων με δυνατότητα διαγραφής

## Εγκατάσταση και Εκτέλεση

### Προαπαιτούμενα
- XAMPP (Apache + MySQL)
- Web browser

### Βήμα 1 — Εγκατάσταση XAMPP
Κατεβάστε το XAMPP από https://www.apachefriends.org/ και εγκαταστήστε το. Εκκινήστε Apache και MySQL από το Control Panel.

### Βήμα 2 — Αντιγραφή αρχείων
Αντιγράψτε τον φάκελο `energy_monitor` στο:
C:\xampp\htdocs\energy_monitor\

### Βήμα 3 — Δημιουργία βάσης δεδομένων
1. Ανοίξτε http://localhost/phpmyadmin
2. Δημιουργήστε νέα βάση με όνομα `energy_monitor`
3. Κλικ Import → επιλέξτε το αρχείο `database.sql` → Go

### Βήμα 4 — Εκτέλεση
Ανοίξτε τον browser και πηγαίνετε στη διεύθυνση:
http://localhost/energy_monitor/

## Δικτυακή Αρχιτεκτονική — Μέρος Β

Η δικτυακή τοπολογία υλοποιήθηκε στο Cisco Packet Tracer.

### Τοπολογία
- **Τύπος:** Κυκλική (Ring Topology)
- **5 Routers:** R1, R2, R3, R4, R5 (μοντέλο 1841)
- **2 Switches:** SW1, SW2 (μοντέλο 2950-24)
- **1 Server-PT:** Φιλοξενεί την HTML σελίδα της εφαρμογής
- **1 PC-PT:** Προσπελαύνει την εφαρμογή μέσω browser

### Πρωτόκολλο Δρομολόγησης
Χρησιμοποιήθηκε **OSPF (Open Shortest Path First)** — Area 0.

Το OSPF επιλέχθηκε γιατί:
- Χρησιμοποιεί τον αλγόριθμο Dijkstra για εύρεση βέλτιστης διαδρομής
- Δεν έχει περιορισμό στον αριθμό των hops (το RIP έχει μέγιστο 15)
- Είναι κατάλληλο για κυκλικές τοπολογίες
- Συγκλίνει γρηγορότερα από το RIP

### IP Addressing Plan

| Συσκευή | Interface | IP Address | Subnet Mask |
|---------|-----------|------------|-------------|
| Server0 | FastEthernet0 | 192.168.1.10 | 255.255.255.0 |
| R1 | FastEthernet0/0 | 192.168.1.1 | 255.255.255.0 |
| R1 | Serial0/0/0 | 10.0.12.1 | 255.255.255.252 |
| R1 | Serial0/0/1 | 10.0.51.2 | 255.255.255.252 |
| R2 | Serial0/0/0 | 10.0.12.2 | 255.255.255.252 |
| R2 | Serial0/0/1 | 10.0.23.1 | 255.255.255.252 |
| R3 | Serial0/0/0 | 10.0.23.2 | 255.255.255.252 |
| R3 | Serial0/0/1 | 10.0.34.1 | 255.255.255.252 |
| R4 | Serial0/0/0 | 10.0.34.2 | 255.255.255.252 |
| R4 | Serial0/0/1 | 10.0.45.1 | 255.255.255.252 |
| R5 | Serial0/0/0 | 10.0.45.2 | 255.255.255.252 |
| R5 | Serial0/0/1 | 10.0.51.1 | 255.255.255.252 |
| R5 | FastEthernet0/0 | 192.168.2.1 | 255.255.255.0 |
| PC0 | FastEthernet0 | 192.168.2.10 | 255.255.255.0 |

### Έλεγχος Συνδεσιμότητας
- ping 192.168.1.10 από PC0 → επιτυχές (3/4 packets)
- tracert 192.168.1.10 → διαδρομή μέσω R5 → R1 → Server0
- Web Browser PC0 → http://192.168.1.10/index.html → εμφάνιση Energy Monitor
